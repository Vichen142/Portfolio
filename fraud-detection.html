Overview

This is an end-to-end fraud classification pipeline. It handles severe class imbalance with targeted sampling and feature engineering, compares Logistic Regression, Random Forest and XGBoost, and judges them with Precision-Recall curves instead of accuracy.

The problem

In fraud data, almost every transaction is legitimate. A model that predicts "not fraud" every time can score a very high accuracy and still be useless, because it never catches a single fraudulent transaction.

The challenge was to build a model that finds the rare cases without burying analysts in false alarms, and to measure it with the right metric.

How I built it

  1. Explore and clean the data

    Check the class balance, look for gaps and outliers, and prepare the data for modelling with Pandas.

  2. Engineer features

    Create inputs that help the models tell normal behaviour from suspicious behaviour.

  3. Rebalance with SMOTE

    SMOTE creates synthetic fraud examples by interpolating between real ones. The resampling is applied to training data only, so the test set still looks like the real world.

  4. Train and compare three models

    Logistic Regression is the simple baseline, Random Forest adds non-linear power, and XGBoost is the boosted contender.

  5. Judge them on Precision-Recall

    Accuracy hides the problem, so each model is compared on how well it balances catching fraud (recall) against raising false alarms (precision).

What I learned

Accuracy is a trap on imbalanced data. Once I switched to Precision-Recall, the real differences between the models finally became visible, and I learned to ask what a metric actually rewards before trusting it.

What I would do next: tune the decision threshold around the real cost of a missed fraud versus a false alarm, and test cost-sensitive learning as an alternative to resampling.
